Non-negotiable guardrails for any agent session in this repository. These restate and extend CLAUDE.md; where they overlap, both apply.

1. Source of truth: references/fedramp-consolidated-rules.json (the FedRAMP Consolidated Rules for 2026 (CR26) dataset) and the pinned official schemas in artifacts/schemas/official/. Verify both against live upstream by hash at session start and record the check in steering/source-register.txt.
2. Never fabricate compliance facts. Statuses only move on real evidence plus human sign-off. Generative output is never deterministic telemetry and never flips a status to Implemented.
3. Never commit or push without the owner's explicit instruction, and never before validate_sdr.py reports 0 hard failures for every class being shipped.
4. Never add customer-identifying material to this repository. Per-customer work happens in separate private repositories.
5. Edit only sdr/records/records-store.json and the pipeline scripts; regenerate everything else. Generated files are build outputs, not documents.
6. Consult github.com/FedRAMP/rules before deciding. Before changing any code that encodes a FedRAMP requirement, and before answering any question about what FedRAMP requires, resolve the claim against the pinned dataset and quote the rule identifier and its statement. A SessionStart hook reads the dataset, both official schemas, the dataset's own JSON schema, FedRAMP's AGENTS.md and the published rules page at the start of every session, and reports whether the pinned copies still match upstream. If that report says a source CHANGED, or says the check was INCOMPLETE, say so before doing other work rather than answering as though currency were confirmed.
7. Never invent a rule identifier. Check that it resolves in the dataset before writing it into code, documentation or a reply. Rules are nested as FRR -> process -> data -> applicability -> subset -> requirement ID, where applicability is all, 20x or rev5, so an index built only from data['all'] hides every 20x-only rule (all the CSX ones) and will make real identifiers look fabricated. A requirement carries either a single statement plus force, or a varies_by_class object with a different statement and force per class. FedRAMP documents this shape in its own AGENTS.md, mirrored at ../hooks/fedramp-upstream/AGENTS.md.
