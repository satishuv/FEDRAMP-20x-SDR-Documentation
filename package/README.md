# Certification Package

FedRAMP 20x `FRC-CSO-PKG` defines the initial Certification Package as more than the Security Decision Record (SDR). This directory records the whole package boundary and states plainly which artifacts the framework generates today and which are planned, so no reader mistakes the SDR output for a complete package.

See [certification-package-manifest.json](certification-package-manifest.json) for the machine-readable version.

## What the initial package requires

| Artifact | CR26 rules | Required | This repository |
|---|---|---|---|
| Certification Package Overview (CPO) | `FRC-CSO-PKG`, `CPO-CSO-OVR` | Yes | Implemented. `package/cpo/cpo.json` + `.md`, generated by `build_cpo.py`, validated against the official CPO schema. Provider values are TBD placeholders until filled. |
| Security Decision Record (SDR) | `SDR-CSO-FRR`, `SDR-CSX-KSI`, `SDR-CSX-KMT` | Yes | Implemented. JSON plus human-readable, with required semantic items carried and validated. |
| Ongoing Certification Report (OCR) | `FRC-CSO-PKG`, `CCM-OCR-AVL` | Yes, and every 3 months | Example implemented. `package/ocr/ocr-example.json` + `.md`, generated by `build_ocr.py`, validated against the official OCR schema. Satisfies the real-or-example requirement; a provider replaces the EXAMPLE summaries and regenerates quarterly. |
| Secure Configuration Guide (SCG) | `SCG-CSO-RSC`, `SCG-CSO-AUP` | Class B and C | Scaffold implemented. `package/scg/secure-configuration-guide.md`, generated by `build_scg.py` with the required sections and TBD placeholders. FedRAMP publishes no JSON schema for the SCG, so it is not schema-validated. |
| Certification data sharing | `CDS-CSO-*` | Yes | Partial. Paired JSON and human-readable outputs support `CDS-CSO-CBF`; a trust center (`CDS-CSO-UTC`) and Class C availability service (`CDS-CSO-AVR`) are not implemented. |
| Incident Report, Significant Change Notification, Vulnerability artifacts | `IEC-CSO-IIR/OIR/FIR`, `SCN-CSO-HRM`, `VDR`/`VER` | Event-driven | Example implemented. `package/events/`, generated by `build_events.py`. Three incident examples (Initial/Ongoing/Final) against the one unified schema; the SCN is generated in both JSON and human-readable Markdown (SCN-CSO-HRM); each JSON artifact validated against its official schema. Empty arrays attest none-this-period. |

## Scope honesty

This repository generates the SDR, the Certification Package Overview, and an example Ongoing Certification Report, each validated against its official FedRAMP schema. It also generates a Secure Configuration Guide scaffold (Markdown, no official JSON schema exists for it) and the event-driven artifacts: three incident-report examples (Initial, Ongoing, Final), a Significant Change Notification in both JSON and human-readable form (SCN-CSO-HRM), and the vulnerability set, each JSON artifact validated against its official schema. What is NOT implemented is called out precisely in the table above and below: certification data sharing is partial (no trust center, no Class C availability service), and the Class A External Assessment Materials are modeled as references only (the repository stores no confidential reports).

Nothing in this directory is a compliance claim. A public GitHub Pages site is not a FedRAMP-compatible trust center, OSCAL is an interoperability export and not a native 20x submission format, the OCR is an example with placeholder summaries, and every generated artifact remains an unverified draft until a qualified human confirms it. See the caution banner in the top-level [README](../README.md).
